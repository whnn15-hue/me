# 제출본 중심 사진 재활용 미리보기

2026-10-25 사용자 수정 반영: 원래 수업을 필수 기준으로 삼지 않는다. 공모전이나 연구대회에 제출한 보고서와 첨부 파일을 모으고, 선택한 사진을 해당 제출본에 연결한다. 수업 연결은 선택 사항이다.

## 이번 범위

- 대분류 이력, 수업, 강의 자료, 대학원 유지. 이력 아래 공모전 제출본, 수업 아래 사진 보관함을 추가했다.
- JPG, PNG, WEBP 최대 50장 업로드, 파일당 25 MB, 한 번에 합계 200 MB. 같은 바이트의 파일은 SHA-256으로 중복 제외한다. 검토 상태와 별표, 사진 설명, 태그 검색 및 일괄 검토를 지원한다.
- 제출본에 공모전 이름, 연도, 상태, 제출일, 결과와 원본 파일을 보관한다. 기존 파일도 연결 가능하다. 준비 중 기록과 실제 제출 이력을 구별한다.
- PDF, HWPX, DOCX, TXT 공고에서 텍스트를 읽거나 직접 붙여 넣어 사진 자리를 만든다. 사진 자리와 태그를 수정하고, 태그가 맞는 후보 6장 또는 전체 사진 중에서 선택한다. 이전 사용 이력 때문에 사진을 제외하지 않는다.
- 한 제출본에 같은 사진을 두 번 넣지 않는다. 다른 제출본에서는 같은 사진을 사용할 수 있다. 순서를 바꾸고 제출본별 설명을 저장할 수 있다.
- 선택 사진의 원본 바이트, 순서, 설명 TXT, 제출본 JSON을 ZIP으로 내보낸다. ZIP 다운로드는 현재 편집 상태를 담으며 앱에 보관하려면 제출본 저장을 눌러야 한다.
- 통합 검색과 기존 JSON 백업에 사진 메타데이터와 제출본이 포함된다. JSON 자체에는 원본 파일이 포함되지 않는다.

## 이번 범위에 포함하지 않은 기능

이미지 내용을 읽는 AI, 스캔 OCR, 사진의 자동 장면 판독, 보고서 안의 이미지 추출, 드라이브 임의 폴더 일괄 가져오기, 공모전 자격 자동 판정, 사례 조합 추천, 보고서 초안 생성은 후속 단계다. 이번 추천은 파일명에서 제안한 태그, 사용자가 검토한 태그와 공고 문구에 기반한다. 추천 점수는 공모전 적격성이나 실제 활동의 증빙 판정이 아니다. HWP 원본은 보관할 수 있지만 미리보기 공고 추출은 PDF, HWPX, DOCX, TXT 또는 붙여넣기를 이용한다.

## 저장과 호환성

기존 `workspace` 버전 1의 항목 배열에 `photo`와 `submission` 종류를 추가했다. 기존 항목, 경력, 원본 구조는 재작성하지 않는다. 기존 JSON과 ZIP은 계속 읽을 수 있으며 새 항목도 현재 백업과 Firestore 메타데이터 행에 포함된다. 원본은 기존 document 저장 경로를 사용한다. 사진 원본은 실제 앱에서는 기존 비공개 Drive 저장을 이용한다.

제출본의 사진 설명은 사진 보관함 설명과 독립적으로 저장한다. 연결된 사진은 제출본에서 먼저 연결 해제해야 삭제할 수 있다. 사진/제출본에서 사용 중인 원본도 삭제를 차단한다. 사진이나 제출본 기록만 삭제할 때 원본은 유지된다. JSON 가져오기에서 같은 원본이 다른 ID로 존재하면 사진/제출 파일 참조도 검증된 ID로 바꾼다. 확인할 수 없는 원본은 잘못 연결하지 않고 가져오기를 거절한다.

## 격리된 미리보기

```sh
npm run preview:local
```

이 명령을 실행한 컴퓨터에서 http://127.0.0.1:4173/ 을 연다. 클라우드 작업 공간에서 실행한 localhost 주소는 사용자의 맥 주소가 아니다.

미리보기 빌드는 Firebase 구성값을 비우고 `VITE_PREVIEW_MODE=true`를 고정한다. 예시 경력과 수업만 초기화하며, 추가한 기록과 파일은 해당 주소의 해당 브라우저 IndexedDB에 저장한다. 다른 컴퓨터와 동기화하지 않으며 브라우저 데이터 삭제 시 사라진다. 실제 Firebase 로그인, 드라이브, AI 서버 요청은 실행하지 않는다. 기존 화면의 일부 실서비스 기능은 미리보기에서 사용 불가 메시지를 표시한다.

Netlify의 Deploy Preview와 branch deploy는 별도 빌드 명령과 별도 Functions 폴더를 사용하도록 설정했다. 미리보기 API는 항상 403을 반환하고 예약 백업은 아무 작업도 하지 않는다. production 설정과 환경 변수는 유지했다.

2026-10-25 현재 로컬 빌드와 브라우저 격리만 검증했다. GitHub API가 403을 반환하므로 PR 생성과 Netlify 온라인 미리보기 주소는 아직 확인하지 못했다. 소스 푸시는 `[skip netlify] [skip ci]`를 사용한다. 온라인 미리보기 또는 정식 배포가 완료되었다고 취급하지 않는다.

## 검증

```sh
npm test
npm run build
npx playwright test -c playwright.preview.config.ts
TEST_DESKTOP_ONLY=1 npx playwright test test/workspace-e2e.spec.ts test/home-e2e.spec.ts test/archive-upgrade-e2e.spec.ts
```

미리보기 테스트는 합성 이미지 50장과 가짜 보고서만 사용한다. 외부 요청과 실제 API 요청을 차단하고 요청 횟수가 0인지 검사한다. 중복 제외, 검토, 제출본 연결, 원본 바이트가 동일한 ZIP, 새로고침 후 유지, 설명 분리, JSON 왕복과 기존 이력/수업 보존을 확인한다. 모바일 검증은 사용자의 현재 요청 범위에서 제외한다.

검증 결과: 일반 자동 테스트 253개 통과. 격리된 미리보기의 50장 업로드부터 통합 검색, 삭제 후 원본 재연결까지 통과. 기존 이력, 홈, 수업, 강의 자료, 대학원 관련 데스크톱 시나리오 6개를 확인했다. 초기 실행에서 테스트 산출물 경로 충돌과 예전 모바일/탐색 가정이 발견되어 미리보기 산출물을 별도 폴더로 분리하고 현재 데스크톱 범위에 맞는 탐색으로 수정한 뒤 해당 시나리오를 다시 통과시켰다. production 빌드 및 preview 빌드 모두 통과했다. 운영 데이터로 시험하지 않았다.

## 되돌리기

작업 전 백업 브랜치: `backup/before-submission-photo-preview-20261025` (`5503eb6`). 작업 브랜치: `preview/submission-photo-library`.

미리보기 개발을 취소하려면 변경 내용을 보관한 뒤 백업 브랜치로 전환하면 된다. `main`은 변경하지 않았다. 실제 데이터는 수정하지 않았으므로 이번 작업을 되돌리는 데 운영 데이터 복원은 필요하지 않다. 향후 정식 배포 후 새 종류의 기록을 저장했다면, 코드를 이전 버전으로 되돌리기 전에 새 기록을 포함한 전체 백업을 보관해야 한다.
