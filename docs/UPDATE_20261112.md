# C아카이브 이름과 검토한 증빙

앱 이름을 C아카이브로 통일했습니다. 사이드바, 홈, 로그인, 브라우저 제목과 새로 내려받는 백업 파일명에 적용합니다. 로고는 C와 기록을 나타내는 평면 심벌이며, 사이드바 64px, 홈 72px, 로그인 96px로 표시합니다. SVG와 48px, 180px PNG 아이콘을 함께 제공합니다.

기존 JSON 형식 식별자, 저장소 키, 데이터베이스 이름, 드라이브 폴더와 인증 설정은 유지합니다. 이전 이름의 백업도 그대로 가져올 수 있습니다. 증빙 가져오기 안내는 현재 연결된 드라이브에 맞게 중립적으로 표시합니다.

## 검토한 증빙 묶음

- 원본 PDF 6개, 기존 이력 연결 대상 5건, 신규 이력 0건입니다. 연결 대상은 기존 자료의 ID를 사용하고, 실제 가져오기 화면에서 최신 기록을 읽어 확인합니다.
- 원본 바이트를 보존하고 문서 내용에 맞는 날짜와 제목으로 파일명만 정리했습니다. 스캔 문서의 검색용 전사문을 포함하며 자격 내역의 생년월일과 등록번호는 검색 텍스트에서 제외합니다.
- 공개 파일 `public/imports/91b38165d8a79926.bin`에는 AES-256-GCM 암호문만 들어 있습니다. 원본, 검토 목록과 복호화 코드는 Git에 포함하지 않습니다.
- `백업 및 설정 → 정리한 증빙 가져오기`에서 코드를 붙여넣고 연결을 확인한 뒤 저장합니다. 기존 필드를 덮어쓰지 않으며 동일 원본의 재가져오기는 중복 생성하지 않습니다.
- 묶음 준비와 소스 반영은 실제 계정에 가져오기 완료를 의미하지 않습니다. 현재 실행 환경에는 본인 로그인 세션이 없고 운영 주소에 대한 네트워크 접근도 차단되어 있어 실제 저장과 운영 화면은 독립적으로 확인하지 못했습니다.

## 이전 Netlify 사이트 정리

소유자가 이전 Netlify 프로젝트 `sensational-cuchufli-e3fbc9`의 삭제를 명시적으로 요청했습니다. `netlify.toml`의 빌드 무시 명령으로 후속 Git 빌드를 건너뛰도록 설정했습니다. 이는 기존 게시물이나 배포된 함수를 삭제하지 않습니다. 현재 환경에는 Netlify 인증 수단이 없고 API 연결도 차단되어 있어 실제 삭제는 완료하지 못했습니다. Netlify 프로젝트의 `Project configuration → General → Danger zone → Delete project`에서 해당 프로젝트만 삭제해야 합니다. Firebase, Vercel과 실제 파일 저장소는 삭제 대상이 아닙니다.
