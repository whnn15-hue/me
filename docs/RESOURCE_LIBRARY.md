# 자료실 확장, 2026-10-27

기존 강의 자료 화면을 자료실로 넓힌다. 이력과 수업, 기존 자료의 ID와 링크, 저장 경로는 유지한다. 개발 브랜치는 `preview/resource-library`, 작업 전 백업은 `backup/before-resource-library-20261027` (`363abb5`)이다. 운영 배포 요청은 아직 없으며 main은 바꾸지 않는다.

## 기능

- 강의 자료, 효과음과 오디오, 배경음악, 템플릿, 이미지, 영상, 기타로 분류한다. 목록과 왼쪽 메뉴에서 필터를 선택한다.
- 파일명과 형식으로 분류와 태그를 제안한다. 음성 인식이나 음악 내용 분석은 하지 않는다. 사용자가 분류를 수정할 수 있다.
- 기존 문서와 이미지 업로드에 MP3, WAV, OGG, M4A, FLAC, POTX, DOTX, XLTX를 추가한다. 확장자와 기본 파일 헤더를 함께 검사한다. 기존 PPTX, HWPX 등도 템플릿으로 분류할 수 있다.
- 오디오는 사용자가 들어보기를 누를 때만 본인 드라이브 원본을 읽는다. 보관 폴더와 소유자, 크기와 SHA-256을 확인한 Blob으로 재생하며 자동 재생하지 않는다. 창을 닫으면 Blob URL을 해제한다. 링크만 등록한 외부 오디오는 드라이브에서 연다.
- 자료실의 원본 합계와 용량을 모르는 링크를 구분한다. Google 계정 사용량은 버튼을 눌렀을 때 기존 Drive 권한으로 `about?fields=storageQuota`를 읽는다. 실패하면 0이나 무제한으로 표시하지 않는다. 실제 소유자 계정의 수치는 개발 환경에서 확인하지 않았다.
- 즐겨찾기, 검색, 날짜 정렬, 과목과 기초훈련 필터, 이력과 수업 연결은 유지한다.

## 용량과 백업

파일 원본은 Google Drive, 목록은 기존 Firebase 저장소에 둔다. Netlify에 미디어 원본을 쌓지 않는다. 계정의 실제 남은 Drive 용량은 소유자가 앱에서 조회하거나 https://one.google.com/storage 에서 확인한다. 일반 무료 Google 계정의 기본 저장공간은 15 GB이며 Gmail과 Google 포토 등이 함께 사용하므로 전부 이 앱에 쓸 수 있다고 가정하지 않는다.

직접 업로드는 파일당 25 MiB, 한 번에 10개, 합계 200 MiB이다. 큰 프레젠테이션과 영상은 Drive에 올린 다음 기존 HTTPS Drive/Docs 링크를 등록한다. 수업, 자료, 사진, 제출본 등 workspace 기록은 전체 5,000개와 메타데이터 5 MiB 제한을 유지한다. 자동 백업 전체 목록에도 5 MiB 한도가 있어 다른 기록의 양에 따라 먼저 도달할 수 있다. 파일 원본의 바이트 수와 메타데이터 크기는 별개다.

자료실 파일은 기존 방식대로 공문 테이블에 섞지 않고 workspace의 `fileUrl`, `sourceFile`로 연결한다. JSON/ZIP 및 자동 Drive 백업에는 자료 목록과 원본 링크가 포함된다. 자료실 원본 전체를 ZIP에 복제하는 별도 오프사이트 백업을 구현한 것은 아니다. 원본을 Drive에서 삭제하면 링크와 목록만으로 원본을 복구할 수 없다. 기존 공문 원본을 포함하는 ZIP 백업의 200 MiB 제한도 그대로다.

## 호환성

`material.resourceType`은 선택 필드다. 이전 자료에는 파일명과 형식으로 화면 분류만 계산하고, 일괄 수정하거나 기존 태그를 덮어쓰지 않는다. 수업 자료의 `purpose: classroom`과 기존 강의 자료의 `purpose: lecture` 또는 필드 생략을 유지한다. 따라서 기존 데이터의 일괄 마이그레이션은 필요 없다. 원본 링크를 수동 교체하면 더 이상 일치하지 않는 기존 `sourceFile` 크기와 해시 정보를 제거한다.

새로운 오디오와 이미지 형식, 오디오 원본을 인식하는 검증기를 브라우저, 서버, 백업 리더에 함께 반영했다. 새 자료를 저장한 뒤 구버전 앱으로 내리면 구버전 검증기가 새 형식을 모를 수 있다. 배포 후 되돌릴 경우 데이터는 삭제하지 말고 새 형식 검증 호환성을 유지하는 수정으로 되돌린다. 아직 실제 계정에 새 자료를 넣기 전이라면 작업 브랜치 변경을 버리거나 해당 커밋을 revert하면 된다. 운영 배포는 별도 요청 후 한 번만 한다.

## 검증과 미리보기

합성 파일과 가짜 저장소로 업로드 준비, 형식 위장 거절, 분류와 태그, 링크 교체, JSON/ZIP 왕복, 기존 이력과 수업 연결, 검색과 즐겨찾기, 삭제 충돌을 검사한다. 실제 계정의 Firebase/Drive에 테스트 데이터를 쓰지 않는다. 데스크톱 브라우저에서 WAV 재생, 필요할 때만 원본을 읽는 동작, Blob URL 해제, 계정 용량 조회 실패 표시, 밝은/어두운 테마를 확인한다.

`npm run build:preview`는 기존 격리된 샘플 앱을 만든다. 자료실의 오디오와 용량 UI를 따로 살펴볼 합성 데모는 다음으로 생성할 수 있다. 데모의 용량 수치는 예시이며 실제 Google 계정 값이 아니다. 파일 업로드와 Drive 저장 자체는 이 데모가 수행하지 않는다.

```sh
RESOURCE_PREVIEW_ARTIFACT=/tmp/resource-library-preview.html TEST_DESKTOP_ONLY=1 node --test test/resources-ui.test.mjs
```

주요 수정 파일은 `src/workspace/MaterialsView.tsx`, `AudioPreview.tsx`, `ResourceStorage.tsx`, `shared/resources.mjs`, `shared/material-classification.mjs`와 기존 업로드, 백업 검증기다. 새 라이브러리나 유료 서비스는 추가하지 않았다.
