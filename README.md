# Introduce Me

교사 개인의 경력과 공문을 함께 관리하는 비공개 웹앱입니다. 경력을 등록하고 분류·연도·기관·태그로 검색하며, 필요한 기록과 증빙을 제출용으로 모을 수 있습니다.

## 실행

Node.js 24 이상과 `pdftotext`(Poppler)가 필요합니다. 현재 클라우드 환경에서는 두 가지를 확인했습니다.

```sh
cd /workspace/me
npm ci --cache /workspace/.cache/npm
npm run dev
```

개발 서버는 127.0.0.1의 5173 포트, API는 3001 포트에서 실행합니다. `npm run dev`는 로컬 개발 모드를 명시적으로 켜고 루프백 주소만 허용합니다. 인터넷에 노출하는 실행 방식으로 사용하지 마세요. 구글 계정 없이 현재 환경에서 기능을 개발·검증할 수 있습니다.

```sh
npm run build
npm test
npm run test:e2e
```

E2E는 Chromium(`/usr/bin/chromium`)과 격리된 임시 데이터 디렉터리 및 3002 포트를 사용합니다. 사용자 데이터는 수정하지 않습니다. 다른 머신에서는 `CHROMIUM_PATH`로 설치된 실행 파일을 지정하세요.

빌드 후 `npm start`로 서버와 빌드된 화면을 함께 실행합니다. `.env`가 있으면 Node가 읽으며, 실제 운영은 환경 변수 주입을 권장합니다. `.env.example`에 필요한 **이름만** 있습니다. 값을 저장소에 커밋하지 마세요.

## 구현한 기능

- 현재 개발 환경에는 PDF에서 가져온 65개 경력 후보가 있습니다. 전부 확인 전이며 실제 공문 연결은 없습니다. 개인 후보와 원본 PDF는 Git 및 웹 배포에 포함하지 않습니다. 새 보관함은 비어 있습니다.
- 경력 직접 등록·수정·삭제, 자유 서술을 초안으로 정리, 연도/분류/증빙 필터와 검색, 목록/카드 보기
- 공문 여러 개 업로드, 파일 SHA256 중복 검사, 경력에 여러 공문 연결, 원본 다운로드. 원본과 경력의 저장은 서버에서 이루어져 새로고침·서버 재시작 후 유지됩니다.
- PDF/HWPX/DOCX/TXT 텍스트 추출. HWP/XLSX는 원본 보관·연결을 지원하고 내용은 직접 입력합니다. HWP는 한글에서 HWPX/PDF로 변환하면 추출할 수 있습니다.
- 외부 AI 연결 시 문서/이미지 분석. 연결 전 또는 실패 시 **규칙 기반 분석**임을 표시하고 사용자 확인 후 저장합니다. AI가 추출한 항목을 검증하고 불명확한 값은 비워두게 요청합니다. 업로드 파일에 적힌 지시는 앱의 명령으로 취급하지 않습니다.
- 경력을 선택해 이력서 미리보기, 내용 복사, CSV, 인쇄/PDF 저장, 연결된 원본과 경력 목록을 담은 증빙 ZIP
- HWPX 양식의 표 셀을 읽어 사용자가 지정한 칸에 선택한 경력·이름·직접 작성한 내용을 입력. 다른 XML·서식·구조는 보존합니다. HWP 바이너리 자동 입력은 지원하지 않습니다. 복잡한 양식은 한글에서 결과의 셀 높이·줄바꿈·서식을 최종 확인하세요. 실제 제출 양식으로의 호환성은 추가 검증이 필요합니다.
- 전체 ZIP 백업·복원. 원본 SHA256, ZIP 경로·크기·무결성, 경력 연결을 검증하고 복원하며 로그인 정보·비밀값은 백업에서 제외합니다.
- 본인 구글 계정 전용 로그인, 별도 권한의 구글 드라이브 연결. 무료 배포에서는 공문 원본을 Drive에 보관하고 Netlify 예약 함수가 하루 한 번 경력·공문 연결 정보를 날짜별로 백업합니다. 원본과 정보를 모두 담은 ZIP은 브라우저에서 만들어 다운로드할 수 있습니다. 로컬 서버는 실행 중일 때 ZIP을 자동 백업합니다.
- 모바일 화면, 키보드 탐색, 경력 편집 및 복원/삭제 확인

## 무료 배포와 다른 컴퓨터에서 사용하기

기본 배포는 **Firebase Spark + Netlify Free + Google Drive**입니다. Firebase Authentication은 구글 로그인을, Firestore는 경력·공문 연결 정보를, Drive는 원본과 백업을 저장합니다. Netlify 함수가 Drive 연결·백업·문서 분석을 처리하고, 인증 토큰은 비공개 Netlify Blobs에 암호화해서 보관합니다. Firebase Storage·Cloud Functions·Blaze 업그레이드는 필요하지 않습니다.

[무료 배포 안내](docs/FREE-DEPLOY.md)를 따라 새 프로젝트와 사이트에 설정하세요. 본인 이메일로 제한한 Firestore 규칙과 서버 `OWNER_EMAIL`을 함께 적용해야 합니다. 웹 설정만 등록하면 로그인·저장·Drive 연결이 모두 완료되는 것은 아닙니다.

```sh
npm run prepare:cloud -- --help
```

설정 도구의 기본값은 `--mode free`이며 로컬 설정 파일만 생성합니다. `VITE_` 변수는 브라우저에 공개됩니다. Google OAuth 비밀값과 선택적인 Gemini 키는 Netlify 서버 환경 변수에만 입력하세요. 무료 AI 키가 없으면 기본 규칙으로 분류·추출하고 확인 후 저장합니다. 무료 배포는 OpenAI 키를 사용하지 않습니다.

무료 서비스의 저장 공간·호출 수·실행 시간 한도 내에서 사용하는 구성입니다. Netlify 사이트는 Free 요금제를 확인하고 Firebase는 Spark를 유지하세요. 자동 백업은 짧은 함수 실행 시간에 맞춰 경력·연결 정보를 저장하고, 이미 Drive에 저장한 원본을 참조합니다. 원본을 유지해야 과거 백업도 복원할 수 있으므로 앱에서 공문 항목을 삭제해도 Drive 원본은 보존합니다. Drive에서 직접 원본을 삭제하면 해당 백업의 복원이 불가능할 수 있습니다. 전체 ZIP은 브라우저에서 생성하므로 처리 중 창을 유지하세요. 백업 성공 시각과 Drive의 날짜별 파일을 확인하고, 실제 배포 후 본인 로그인·다른 계정 차단·새로고침 후 저장 유지·원본 다운로드·백업·복원을 검증해야 합니다.

현재 개발 환경의 65개 기록은 `.cloud-local/initial-career-backup.zip`에 개인 백업으로 남겨두었습니다. 본인 로그인과 Drive 연결 후 안전하게 복원해 옮겨야 합니다. 소스 저장소에 이 파일을 추가하지 마세요. 클라우드 환경 설정을 게시하는 것과 웹앱을 HTTPS 주소로 배포하는 것은 별개입니다.

## 영구 디스크가 있는 로컬 서버의 운영

실제 다른 컴퓨터에서 쓰려면 앱을 HTTPS 주소로 배포하고, `/data` 같은 **영구 저장 디스크**를 연결해야 합니다. 클라우드 개발 환경 설정을 게시하는 것과 웹앱을 인터넷에 배포하는 것은 별개입니다. 개발 환경의 실행 중 프로세스는 다음 작업으로 이어지지 않을 수 있습니다.

1. Google Cloud Console에서 프로젝트를 만들고 OAuth 동의 화면을 설정합니다. 개인용 테스트라면 본인 계정을 테스트 사용자에 추가합니다. Drive API를 활성화합니다.
2. OAuth 클라이언트를 **웹 애플리케이션** 유형으로 만듭니다. 승인된 리디렉션 URI는 `APP_URL`의 origin + `/api/auth/callback`입니다. 예: `https://your-app.example/api/auth/callback`. 로컬 테스트는 `http://127.0.0.1:5173/api/auth/callback`을 등록합니다.
3. `APP_URL`, `OWNER_EMAIL`(본인 구글 이메일), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`을 설정합니다. 운영에서는 `APP_LOCAL_MODE=false`를 유지합니다. 서버는 지정한 이메일의 인증된 계정만 허용합니다.
4. 앱의 구글 로그인 후 ‘백업 및 설정’에서 드라이브 권한을 별도로 연결합니다. 최소 `drive.file` 권한으로 앱이 만든 백업 폴더와 파일만 다룹니다. 연결 해제는 자동 백업을 중지하며 기존 백업을 삭제하지 않습니다.
5. ‘지금 백업하기’의 성공 시각을 확인하고, 새 컴퓨터에서 로그인해 경력·원본 열기를 확인합니다. 현재 환경에서는 OAuth 자격 증명이 없어 이 외부 연결은 아직 실서비스로 검증하지 않았습니다.

동의 화면이 테스트 상태이면 Google 정책에 따라 갱신 토큰이 만료되어 다시 연결해야 할 수 있습니다. 백업 오류는 설정 화면에 표시됩니다. 자동 백업은 서버가 실행 중이어야 하며 영구 저장 공간과 실제 API 연결이 필요합니다.

OpenAI 분석은 `APP_AI_KEY`를 안전하게 설정하면 켜집니다(모델 기본값 `gpt-4.1-mini`, 선택적으로 `APP_AI_MODEL`). 문서 내용은 해당 서비스로 전송됩니다. `APP_AI_KEY`는 플랫폼 예약 이름을 피한 앱 전용 변수입니다. 서비스 비용은 연결 계정에서 발생합니다. AI 설정 여부와 실제 연결 검증은 다릅니다.

필요한 네트워크 대상: `accounts.google.com`, `oauth2.googleapis.com`, `openidconnect.googleapis.com`, `www.googleapis.com`, `api.openai.com`. 설치는 `registry.npmjs.org`를 이용합니다. 기본 TLS 인증서·패키지 무결성 검증을 유지합니다.

## 데이터 보관

`APP_DATA_DIR`(기본 `.data`)에 SQLite DB, 원본 파일, Drive 토큰 암호화 키가 저장됩니다. SQLite에는 경력과 연결 정보가 저장되고, Drive 토큰은 AES-GCM으로 암호화됩니다. 이 디렉터리는 개인 데이터이므로 저장소에 포함되지 않습니다. 운영 디스크의 접근 권한을 제한하세요. 암호화 키를 잃으면 Drive 재연결이 필요합니다.

파일당 최대 25 MB, 업로드 한 번에 10개, 복원 ZIP 최대 200 MB입니다. 백업 총량이 한도를 넘으면 오류를 표시합니다. 증빙별 묶음으로 원본을 보관할 수 있으나 부분 묶음 복원은 전체 데이터를 그 묶음으로 교체하므로 전체 백업과 구분하세요. 복원 전 현재 데이터를 백업하세요.

새 데이터 디렉터리는 최초 한 번만 초기 경력을 가져옵니다. 초기 경력 원본 PDF의 공문 파일명은 실제 첨부 파일이 아닙니다. AI/OAuth 키, 암호화 키, 세션 정보는 백업 ZIP에 포함되지 않으며 복원 후 다시 설정·연결해야 할 수 있습니다. 복원은 현재 기록 전체를 교체합니다.

## 배포 패키지

`Dockerfile`은 Node 24·Poppler·빌드된 앱을 포함하며 기본적으로 구글 인증을 요구합니다. HTTPS 프록시와 영구 볼륨(`/data`, 컨테이너의 node 사용자에게 쓰기 권한)을 제공하는 호스트에서 사용할 수 있습니다. Docker 이미지는 이 환경에서 빌드·배포하지 않았습니다. 소스 작업은 기존 체크아웃을 사용하며, 사용자가 요청하지 않는 한 별도 Git worktree를 만들지 않습니다.

## Firebase Functions를 사용하는 선택적 배포

[별도 배포 안내](docs/DEPLOY.md)는 Firebase Blaze 및 Cloud Functions·Storage를 사용하는 선택적 구성입니다. 사용자가 요청한 무료 기본 배포에는 적용하지 않습니다. Cloud Functions는 Node 22로 별도 빌드합니다.

```sh
npm run build:functions
```

유료 구성은 `--mode paid`로 설정 도구를 실행하고 별도 안내의 Netlify 정적 배포 설정을 적용해야 합니다. Firebase 공개 웹 설정이 없으면 설정 안내 화면을 표시합니다. 설정이 없어도 경력 데이터를 공개하거나 로컬 개발 모드로 우회하지 않습니다.

개인 경력 `server/seed.json`, 실제 데이터 `.data`, 개인 백업 `.cloud-local/initial-career-backup.zip`은 Git과 웹 배포 번들에서 제외합니다. 현재 개발 환경에는 PDF에서 정리한 65개 기록이 남아 있습니다. 새 클라우드 보관함은 비어 있으며 본인 로그인 후 개인 백업을 복원해 옮깁니다. 새로 Git에서 받은 개발 체크아웃도 개인 초기 데이터가 없어 빈 보관함에서 시작할 수 있습니다.

배포 설정 파일과 테스트는 실제 배포 완료를 의미하지 않습니다.
